# Resource: auth0_experiment

Create and manage an Experiment Center experiment. (EA only)

## Example Usage

```terraform
resource "auth0_experiment_feature_flag" "login_ui" {
  name        = "new-login-ui"
  description = "Controls whether the new login UI is shown."

  parameters {
    name  = "show_new_login"
    type  = "boolean"
    value = "false"
  }

  # Activate the flag in a later apply, after both variations exist.
  # status = "active"
}

# A control variation has no overrides, so it serves the flag defaults.
resource "auth0_experiment_feature_flag_variation" "control" {
  feature_flag_id = auth0_experiment_feature_flag.login_ui.id
  name            = "control"
}

resource "auth0_experiment_feature_flag_variation" "new_login" {
  feature_flag_id = auth0_experiment_feature_flag.login_ui.id
  name            = "new-login"

  overrides {
    name  = "show_new_login"
    type  = "boolean"
    value = "true"
  }
}

# Percentage strategy: split traffic between variations by weight.
resource "auth0_experiment" "percentage" {
  name                = "login-ui-percentage-test"
  description         = "Show the new login UI to half of the traffic."
  feature_flag_id     = auth0_experiment_feature_flag.login_ui.id
  authentication_flow = "authentication"
  allocation_strategy = "percentage"

  # Omit `status` or set it to "draft" on creation. Set it to "active" in a
  # later apply, after the feature flag is active. An active experiment
  # cannot be deleted: set it to "paused" or "completed" before destroying it.
  status = "draft"

  allocations {
    variation_id = auth0_experiment_feature_flag_variation.control.variation_id
    is_control   = true
    weight       = 50
  }

  allocations {
    variation_id = auth0_experiment_feature_flag_variation.new_login.variation_id
    is_control   = false
    weight       = 50
  }

  # To ramp exposure in steps, remove `weight` from every `allocations` block
  # and set the levels instead:
  # levels = [10, 50, 100]

  # Set `default_config` to "tenant" or "flag" only for an Auth0-managed flag.
  # default_config = "flag"
}

resource "auth0_experiment_segment" "us_traffic" {
  name = "us-traffic"

  rules {
    match {
      country {
        contains = ["US"]
      }
    }
  }
}

# Segment strategy: route each segment to a variation; other traffic gets the
# fallback allocation.
resource "auth0_experiment" "segment" {
  name                = "login-ui-segment-test"
  description         = "Keep US traffic on the current login UI and show the new UI elsewhere."
  feature_flag_id     = auth0_experiment_feature_flag.login_ui.id
  authentication_flow = "mfa_challenge"
  allocation_strategy = "segment"
  status              = "draft"

  # Each targeted allocation sets a segment and a unique priority, where 1 is
  # the highest. Segment allocations do not use `weight` or `levels`.
  allocations {
    variation_id = auth0_experiment_feature_flag_variation.control.variation_id
    is_control   = true
    segment_id   = auth0_experiment_segment.us_traffic.id
    priority     = 1
  }

  # The fallback allocation serves traffic that matches no segment. Omit
  # `segment_id` on the fallback.
  allocations {
    variation_id = auth0_experiment_feature_flag_variation.new_login.variation_id
    is_control   = false
    is_fallback  = true
  }
}
```

## Schema

### Required

- `allocation_strategy` (String) The traffic allocation strategy. One of percentage, segment. Changing this replaces the experiment.
- `authentication_flow` (String) The authentication flow targeted by the experiment. One of authentication, mfa_enrollment, mfa_challenge, password_reset, passkey_enrollment, all.
- `feature_flag_id` (String) The ID of the feature flag evaluated by this experiment. Changing this replaces the experiment.
- `name` (String) The name of the experiment.

### Optional

- `allocations` (Block List) The ordered traffic allocations. At least one is required when configured. Removing all allocations replaces the experiment. (see [below for nested schema](#nestedblock--allocations))
- `default_config` (String) The configuration source for an Auth0-managed feature flag. One of tenant, flag. Removing it replaces the experiment.
- `description` (String) Description of the experiment.
- `levels` (List of Number) The ordered ramp levels. Only for the percentage strategy. Removing them replaces the experiment.
- `status` (String) The lifecycle status of the experiment. One of draft, active, paused, completed, archived. On creation, omit it or use draft. You can update the status after creation. An active experiment cannot be deleted.

### Read-Only

- `created_at` (String) The ISO 8601 formatted date the experiment was created.
- `current_level` (Number) The current ramp level, if levels are configured.
- `editable_fields` (List of String) Fields that the API reports as editable.
- `ended_at` (String) The ISO 8601 formatted date the experiment was completed.
- `feature_flag_name` (String) The name of the feature flag evaluated by this experiment.
- `feature_flag_snapshot` (String) The snapshot of the feature flag.
- `id` (String) The ID of this resource.
- `is_valid` (Boolean) Whether the experiment is ready to activate.
- `started_at` (String) The ISO 8601 formatted date the experiment was first activated.
- `updated_at` (String) The ISO 8601 formatted date the experiment was updated.

### Nested Schema for `allocations`

Required:

- `is_control` (Boolean) Whether this allocation is the control variation. At most one allocation can be the control.
- `variation_id` (String) The ID of the feature flag variation assigned to this allocation.

Optional:

- `is_fallback` (Boolean) Whether this allocation is the fallback. Only for the segment strategy.
- `priority` (Number) The evaluation priority of this allocation. Only for the segment strategy.
- `segment_id` (String) The segment targeted by this allocation. Only for the segment strategy. Omit for the fallback allocation.
- `weight` (Number) The percentage weight of this allocation. Only for the percentage strategy. Omit when using levels.
